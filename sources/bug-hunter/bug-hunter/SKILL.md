# 发现-bug 工作流

把「读代码猜」换成「分层流水线」。六阶段，每阶段产出可被下一阶段消费。

## 何时用

- 用户要求审计 / 找 bug / 排查稳定性或功能性缺陷
- 接手陌生项目，需要快速定位问题富集区
- 已有初步发现，需要系统性地扩大覆盖面

## 快速开始

```bash
# 全量（约 43s）
python3 scripts/pipeline.py <repo> [--root butler] [--top 15] [--json out.json]

# 快速核心扫描（约 2.5s，推荐迭代时用）
python3 scripts/pipeline.py <repo> --fast --focus 30
```

`--fast` 是两阶段：Phase A 正则预筛全仓 → Phase B 只对 top-K 做 AST 精扫。
实测 focus=30 → 58% 召回 / 扫 13.6% 文件；focus=80 → 88% 召回。
**未读文件有 1.6× 权重**（混合聚焦），否则 core 会被已读烂的文件占满。

exit code 即结论：`0` 全通过 / `1` 行为验证未全绿 / `2` 工具缺失（结论需谨慎）。

## 六阶段

| 阶段 | 做什么 | 产出 |
|---|---|---|
| S0 环境体检 | 工具可用性，缺失即降级并标红 | 降级清单 |
| S1 候选生成 | vulture 死代码、ruff 未定义名、radon 复杂度、自写 AST 反模式 | 候选池 |
| S2 优先级排序 | 复杂度 × 枢纽度 × 历史缺陷密度 | 「下一轮读什么」地图 |
| S3 不变量断言 | 属性证伪（**自动发现层**） | 未预料形状的缺陷 |
| S3b 同类扩散 `propagate.py` | 用已实锤缺陷的形状搜全仓同类 | 同款缺陷的第二、第三处 |
| S4 行为验证 | 对接既有 pytest 套件（正测 + 反测） | 实锤 / 反测通过 |
| S5 报告 | 汇总 + exit code | 结论 |

## 三条不可违背的纪律

这三条都是真实踩过的坑，写在代码注释里，改脚本时不要删。

### 1. 工具缺失 ≠ 无问题

沙箱重置过 3 次，每次工具全丢。若那时流水线照常输出「0 缺陷」，等于把缺陷洗白。

→ 体检缺失必须显式降级 + 报告顶部标红 + `exit 2`。

### 2. ERROR ≠ REFUTED

用例自身失败（依赖缺失 / 桩件失效）不能解读为「缺陷不存在」。曾因缺 `paho-mqtt` 导致真实缺陷被误判为「未复现」。

→ 三态：`FOUND` / `REFUTED` / `ERROR`。ERROR 必须 exit 非 0。

### 3. 反测不许假通过（第十轮有了实证）

曾因 `or True` 让反测无条件通过。**第十轮更险**：我给 V25 写的第一版修复方案
（只加双重检查、仍先赋值后 init）经反测实测**完全无效**（半初始化连接仍 7 次），
被拦下后改成"初始化完成后再发布"才归零。
**若反测写得宽泛，这个错误修法会当成已验证通过写进报告。**

曾因 `or True` 让反测无条件通过，输出 23 条无意义噪声。**留着假通过的反测比没有反测更危险。**

→ 反测断言必须精确盯住单个名字/行为，不做宽泛扫描。

## 各层的边界（重要）

- **S1 是模式匹配**：得先知道 bug 长什么样才能写规则。它能提高覆盖率（人工 10% → 接近 100%），但**不能理解代码**。
- **S3 是属性断言**：先声明系统必须恒真的事，再让代码去证伪。**只有这一层能发现没预料到的形状。** 新增不变量是最有价值的扩展方式。
- **两层都不能替代运行时验证**。完整 lifespan、真实外部依赖、并发，工具一个都帮不上——这些必须显式列为未验证项。

## 第十三轮的套件增强（必读）

**补齐 10 个缺失反测**：V1-V6 / V14-V16 / V19 此前只有正测。
正测是探针，反测才是防线 —— 没有反测的场景，修完无法确认是否真修好。
现 **27 场景 × (正测+反测) = 54 条，覆盖率 100%**。

**补齐 V22/V23**：这两条（V23 是 P0，唯一能挂死进程）在第七、八轮就发现了，
却**从未注册进 SCENARIOS**，中间六轮无法回归、无法验证修复。
根因是注册靠手工、漏了不报错 —— 遂新增 `selftest()` + `test_suite_selftest`。

**ERROR ≠ REFUTED 落到 pytest**：新增 `InfraError`。
历史上三次把工具故障读成缺陷结论（缺 paho / 沙箱重置 / radon 不在 PATH）。
抛 `InfraError` → pytest 标记 `INFRA-ERROR`，session 末尾单独汇总，
**既不计入"已通过"也不计入"已推翻"**。

**bootstrap.sh**：沙箱会重置，依赖全丢。过去十三轮因此中断 ≥6 次。
一条命令装齐 25 个依赖（核心/可选/测试增强三组）。

### 反测自身的三种缺陷（第十三轮踩全了）

| 症状 | 真因 | 教训 |
|---|---|---|
| V1* 通过但房间样本为空 | 断言 vacuously true | **空集合会让断言白送通过**，必须断言非空 |
| V5*/V6* 失败 | 我猜错了属性名 / 替换串没命中 | 反测失败先怀疑**反测自己** |
| V19* 抛 FileNotFoundError | radon 不在 PATH | 工具缺失要抛 `InfraError`，不是 `assert` 失败 |

**留着假通过的反测比没有反测更危险。**

## 并发层（第十五轮新增）

`python3 scripts/concurrency.py` —— 专治「静态读代码证不实的并发缺陷」。

四个实验：C1 懒初始化竞态（放大窗口）/ C1* 修法对照 / C2 跨线程写同一连接 / C3 模块级 dict RMW。

**首个能执行证实 P0-2 的层。** 第十五轮第一次跑就产出 2 条实证结论。

### ⚠ 三个环境坑（跑不起来会表现为"没有缺陷"）

| 坑 | 后果 |
|---|---|
| 数据目录环境变量是 **`DATA_DIR`**（默认 `/app/data`），不是 `BUTLER_DATA_DIR` | 用错写进残留库 → **假阴性** |
| 探测半初始化**必须查业务表**，不能查 `sqlite_master` | 表不存在也返回 0 行 → **假阴性** |
| 四个密钥启动期**硬校验** raise | 缺一 → 实验全跑不起来 |

必需：`DATA_DIR` `BUTLER_WEB_USER` `BUTLER_WEB_PASSWORD` `BUTLER_JWT_SECRET`
`BUTLER_ALLOW_NO_AUTH` `DOUBAO_API_KEY` `DESKPILOT_API_TOKEN` `TASK_REPORT_TOKEN`

> 注意：C3 一次 MATCH **不能判安全**（GIL 下调度没撞上而已）。

## 变异测试层（第十四轮新增）

`python3 scripts/mutation.py <相对路径...>` 或 `pipeline.py --mutate <files>`

**存活 = 测试盲区**。回答「这些 passed 有多少真在测东西」。

### ⚠ 三个必须先知道的坑（都已修正，但教训要留）

| 坑 | 假结论 | 修正 |
|---|---|---|
| `rc != 0` 就算 killed | 虚报 **100%** | 必须有真实 `N failed`；`error` 算 invalid 并排除出分母 |
| 测试名不带 `tests/` 前缀 | 全变 invalid | 路径补全 |
| **按文件名 stem 匹配** | **误报 0%** | 改为按真实 import 关系匹配 |

第三个最危险：`triggers/engine.py` 与 `decision/engine.py` 都叫 engine，
stem 匹配把 decision 的测试配给了 triggers，误得「杀死率 0%、测试是空的」。
**手动核查才发现测试有 9 个断言、测的是另一个 engine。**

> 工具报出异常结论（0% 或 100%），先怀疑工具自己。

## 已知误报源（避坑）

| 现象 | 原因 | 处理 |
|---|---|---|
| 原子写检测误判 | 原子写有两种等价写法：`os.replace(tmp,dst)` 与 **`tmp.replace(dst)`（pathlib）** | 两者都要认。`skills/store.py:160`、`triggers/store.py:92` 用的就是 pathlib 形式，只认 `os.replace` 会误判 |
| async 内阻塞调用大量误报 | 同步 helper 被 `run_in_executor` 包裹是合法写法 | 已内置排除，改规则时勿删 |
| 「return 后不可达」上千条 | `if cond: return` 后跟语句是正常控制流 | 该规则已废弃，改用 vulture |
| 未定义名含 `bool`/`str`/`logger` | 内建名、`except as e`、模块级赋值未计入 | 已内置 builtins + 各级赋值收集 |
| 枢纽度全 0 | key 格式不匹配（点号 vs 路径） | 已统一为文件路径 |

## 扩展方式

**加一条反模式规则** → `scripts/stage1_scan.py` 的 `scan_patterns()`，注释必须写明由哪条审计发现反推而来。

**加一条扩散形状** → `scripts/propagate.py` 的 SHAPES（第十轮新增）。
  这一层是"放大器"：它不发现新形状，但能回答"这个 bug 还有没有同款"。
  第十轮用 V23 的形状搜出 34 处、坐实 V24——打破了 R8/R9 的产出递减。

**加一条不变量** → `scripts/invariants.py`，必须写清：源起哪条发现 + **超出该发现还能发现什么**（这是它的价值所在）。

**加一个可执行验证** → 项目 `tests/audit_helpers.py` 的 `SCENARIOS` 注册表。两个坑：
  1. 注册表必须在**文件末尾**，否则其引用的函数尚未定义 → `NameError`（踩过 3 次）。
  2. 新增函数定义要插在注册表**之前**，不能 `>>` 追加（会追加到注册表之后）。

正测断言缺陷存在，反测注入修复后断言恢复正常。
