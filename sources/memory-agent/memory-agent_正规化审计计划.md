### P1 · 结论验证与定级复核（最高优先级）

把前十五轮 26 个缺陷逐个做成**真实运行时 PoC**。

| 状态 | 判据 |
|---|---|
| **CONFIRMED** | 真实模块 + 真实输入 + 观察到预期偏差 |
| **REFUTED** | 真实环境下不成立的，**从总表移除并公开更正** |
| **INCONCLUSIVE** | 依赖真实 HA/LLM，沙箱无法构造 → 标注为待开发者验证 |

**已完成的先行验证（证明方法可行）**：

- **P1-5 CONFIRMED**（真实 `fuse`）：仅人脸→A 得 0.900/HIGH；加一路未匹配信号后 A 跌至 0.600、陌生人 0.900 反超 → `chosen=None`。**新发现**：即使未翻盘（未匹配 0.5 时），置信度仍从 0.900 降到 0.600、等级 HIGH→NEEDS_REVIEW
- **P2-9 CONFIRMED**（真实 `match_device`）：输入"书房电脑开了多久"返回 `switch.study_plug`；**输入"电脑"同样返回插座**

> 真实验证已显现价值：发现了复刻脚本未能暴露的**降级细节**。

### P2 · 动态稳定性测试（此前为 0，本轮核心补强）

| 测试 | 方法 | 判据 |
|---|---|---|
| **并发压测** | 起真实 FastAPI，并发打 `llm_ask` / `debug_routes` / MCP 端点 | 错误率、P99 延迟、500 数 |
| **P2-6 并发丢失实测** | 真实 `_CONV` + 多线程写同一 conversation_id | 实测丢失率（此前仅复刻） |
| **长跑 72h（压缩版）** | 至少 4-8h 连续运行 + 周期任务 | RSS 增长曲线、fd 数、线程数 |
| **内存泄漏探测** | 采样 RSS，拟合增长斜率 | 斜率 >0 且无平台期 = 泄漏 |
| **事件循环阻塞** | 监控 loop lag | >100ms 的阻塞点定位 |

工具：`psutil`（需装）、自建压测脚本、tracemalloc。

## 三、缺陷定级标准（取代此前的主观定级）

此前部分定级基于"推测的触发概率"，未证实。本轮改为：

| 级别 | 判据 |
|---|---|
| **P0** | 可远程利用且导致数据泄露/接管，或导致服务不可用 |
| **P1** | 功能性错误且**已 CONFIRMED**，影响核心业务结果 |
| **P2** | 功能性错误已 CONFIRMED，影响非核心路径；或需特定条件触发 |
| **P3** | 已 CONFIRMED 但影响有限（显示、元数据、可观测性） |
| **P4** | 观察项，无直接功能影响 |

**每个缺陷必须记录**：`PoC 脚本路径 / 真实输入 / 实际输出 / 预期输出 / 影响链路`。

## 七、诚实声明（预先写入）

1. **Python 3.10 < 项目要求 3.11**：可能导致部分依赖行为差异。若某缺陷仅因版本差异无法复现，标 INCONCLUSIVE 而非 REFUTED。
2. **无真实 HA 环境**：依赖 HA 返回的行为无法端到端验证，用 mock + 契约测试替代，并标注。
3. **无真实 LLM**：LLM 相关路径仅测到调用边界。
4. **4-8h 长跑 ≠ 72h**：内存泄漏若增长缓慢可能测不出，会明确写出采样时长与斜率。
5. **沙箱资源受限**：并发压测规模受限，不声称等同于生产负载。
