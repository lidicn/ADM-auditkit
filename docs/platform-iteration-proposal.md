# 审计平台迭代建议 —— 基于 6 轮真实摩擦点

> 来源：AutoForge 6 轮审计的真实摩擦点总结
> 日期：2026-10-11
> 类型：engine / workflow 改进提案

---

## 一句话版本

平台现在的强项是"发现"，弱项是"记忆"。triage 裁决落盘（P1）+ delta/regression 轮次模式（P1）两条落地后，就从"每轮全景重扫"变成"增量守夜"，事半功倍才是常态而非首轮特权。

---

## P0：两个直接可修的平台缺陷

### P0-1：propose create 收集改动文件失败

**问题**：`propose create` 收集改动文件失败——`git status` 明明有 7 个变更，`files_changed: []`，手动补齐才成包。疑似在错误目录跑 git 或只认 staged。

**影响**：提案包自动化无法闭环，每次都要手动补齐文件列表。

**建议**：
1. 确认 `propose create` 在项目根目录跑 `git status`
2. 同时收集 staged 和 unstaged 变更
3. 失败时明确报错，不要静默返回空列表

### P0-2：共享判据变更无联动验证

**问题**：`is_bounded` 一类共享判据（`_common.py`）变更后，只能整轮重跑 553 条来验证 -4 假阳性。

**影响**：校准成本极高——改一个共享判据，要跑完整轮次才能验证效果。

**建议**：规则依赖的共享模块变更时，自动对上一轮该规则的命中集做前后 diff（hit-set diff），分钟级验证召回/精确率变化，不用全量新轮次。

## P1：把"triage 记忆"变成平台能力（本次最大的重复成本）

### P1-1：人工裁决不落盘，下轮重报

**问题**：canary:103、flock:132 这类"语义不成立"的 FP，这次裁了，下个 agent 还得重裁。

**影响**：每轮都要重复 triage 同样的误报，回归轮的 triage 成本极高。

**建议**：加 `auditkit triage accept/reject --reason`，把裁决按 `(rule, file, pattern)` 写进项目 profile；后续轮次自动标"已裁决"，只增量报新命中。

**预期效果**：这一条能把回归轮的 triage 成本砍到接近零。

### P1-2：裁决要区分"不采纳"与"已知未修"

**问题**：C 类 6 条无界容器候选该进 `bugs.json` 台账（status AutoForge 目前没有），修复后复扫归零才算闭合。

**影响**：审计平台和缺陷台账没打通，无法量化"确证率"。

**建议**：
1. 裁决区分两种状态：
   - `rejected`：不采纳（误报，后续轮次自动跳过）
   - `accepted`：已知未修（真 bug，进缺陷台账）
2. 缺陷台账 `bugs.json` 记录：rule_id, file, line, status, fix_round
3. 修复后复扫归零才算闭合

## P1：模式分流——别让老目标付全景全款

### P1-3：轮次模式

**问题**：本次 6 轮里至少 4 轮是重复付全景款——每次都跑全量规则、全量文件。

**建议**：支持 4 种轮次模式：
- `full`：首扫（全量规则 + 全量文件）
- `delta`：只审 `git diff` 涉及文件（活跃仓库边际成本降一个数量级）
- `targeted`：规则子集（只跑指定规则）
- `regression`：仅确证 bug 对应规则（验证修复效果）

### P1-4：规则意图标签

**问题**：给已修复历史缺陷写的规则（cross_func、security_sync）标 0 命中是成功而非可疑，但现在会触发"N1 零命中自检"的排查预算，也进 triage 队列。

**建议**：规则加 `intent` 标签：
- `discovery`：发现新缺陷（0 命中需要排查）
- `regression`：验证已修复缺陷（0 命中是成功，豁免零命中自检，不进 triage 队列）

## P2：降噪与校准摩擦

### P2-1：高噪规则内置收窄变体

**问题**：`silent_except` 319 条没人能逐条看。PITFALLS 里已有方法论（宽捕后是否接全量覆盖写），但只是文档建议。

**建议**：把方法论编成规则变体而非文档建议——319 条能收到个位数高价值命中。

### P2-2：无界容器规则加生命周期启发式

**问题**：按调用构建即弃的 `_Builder`（B 类）与进程级单例 `_history`（A 类）同 severity 报出，本次 29 条里 8 条是这类。

**建议**：对象在函数体内创建且不落 `self/module` → 降级或不报。

### P2-3：规则命中集入库做版本回归

**问题**：规则 bump 版本时，校准从"改-scp-整轮重跑-人眼比对"（本次跑了 3 遍）变成一条命令。

**建议**：规则版本变更时自动 diff 新旧命中集（added/removed），输出变化报告。
